Full system architecture

Nineteen services across three planes, one event spine, one menu-of-record, and a hard local-first boundary at the restaurant edge.

1.1  Topology

The system is a modular monolith at the core with a small number of genuinely independent services carved out where the scaling, latency, or failure profile differs sharply. Resist the urge to start with nineteen deployables; start with four, and split along the seams drawn below as load demands.

1.3  Event spine

Every meaningful state transition publishes a versioned Avro event to Kafka via the transactional outbox pattern (Debezium CDC on an outbox table inside the same Postgres transaction as the state change). This eliminates the dual-write problem: an order is never committed without its event, and never publishes an event for a rolled-back order.

Why Redpanda over Kafka for the first 18 months

Single binary, no ZooKeeper/KRaft operational surface, Kafka wire-compatible, and roughly a third of the infrastructure cost at low volume. Migrating to MSK or Confluent later is a configuration change, not a rewrite, because the client contract is identical. This is a deliberate trade of ceiling for velocity at a stage where velocity is the constraint.

1.4  Order state machine

One state machine governs every order regardless of channel (POS, web, marketplace, phone). Channel affects which transitions are permitted and who may trigger them, never the shape of the machine.

1.5  Database schema — core tables

Postgres 16 with row-level security. Every tenant-scoped table carries org_id as the first column of its primary key and is covered by an RLS policy keyed to a session GUC set by the connection pool at checkout. Money is BIGINT minor units plus an ISO-4217 code; there is no NUMERIC price column anywhere in the transaction path.

Fig. 01.3 — Tenancy, menu, and order DDL (abridged)MD-DDL-001
-- ============ TENANCY ============
CREATE TABLE orgs (
  org_id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  legal_name      text NOT NULL,
  brand_name      text NOT NULL,
  plan_tier       text NOT NULL CHECK (plan_tier IN ('starter','growth','scale','enterprise')),
  processor_acct  text,                      -- connected account ref, never card data
  created_at      timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE locations (
  org_id          uuid NOT NULL REFERENCES orgs,
  location_id     uuid NOT NULL DEFAULT gen_random_uuid(),
  name            text NOT NULL,
  timezone        text NOT NULL,             -- IANA; all business-day math uses this
  geo             geography(Point,4326) NOT NULL,
  address         jsonb NOT NULL,
  service_radius_m int  NOT NULL DEFAULT 8000,
  hours           jsonb NOT NULL,            -- per-service-type, with exceptions
  status          text NOT NULL DEFAULT 'active',
  PRIMARY KEY (org_id, location_id)
);
CREATE INDEX ON locations USING gist (geo);

-- ============ MENU (immutable versions) ============
CREATE TABLE menu_versions (
  org_id          uuid NOT NULL,
  menu_version_id uuid NOT NULL DEFAULT gen_random_uuid(),
  location_id     uuid NOT NULL,
  version_no      bigint NOT NULL,
  content_hash    bytea NOT NULL,            -- sha256 of canonical JSON
  snapshot_uri    text  NOT NULL,            -- s3://…/menu/{hash}.json
  published_at    timestamptz,
  published_by    uuid,
  source          text NOT NULL,             -- 'console'|'ai_optimizer'|'pos_sync'|'import'
  PRIMARY KEY (org_id, menu_version_id),
  UNIQUE (org_id, location_id, version_no)
);

CREATE TABLE items (
  org_id          uuid NOT NULL,
  item_id         uuid NOT NULL DEFAULT gen_random_uuid(),
  sku             text,
  name            text NOT NULL,
  description     text,
  price_cents     bigint NOT NULL CHECK (price_cents >= 0),
  currency        char(3) NOT NULL DEFAULT 'USD',
  cost_cents      bigint,                    -- food cost; drives margin-aware ranking
  prep_seconds    int NOT NULL DEFAULT 300,
  station_code    text NOT NULL,             -- routes the ticket line
  tax_category    text NOT NULL DEFAULT 'prepared_food',
  tags            text[] NOT NULL DEFAULT '{}',
  embedding       vector(768),               -- pgvector, for semantic search + recs
  is_active       boolean NOT NULL DEFAULT true,
  PRIMARY KEY (org_id, item_id)
);

CREATE TABLE modifier_groups (
  org_id uuid NOT NULL, group_id uuid NOT NULL DEFAULT gen_random_uuid(),
  name text NOT NULL,
  min_select int NOT NULL DEFAULT 0,
  max_select int NOT NULL DEFAULT 1,
  selection_type text NOT NULL CHECK (selection_type IN ('single','multi','quantity')),
  PRIMARY KEY (org_id, group_id)
);

-- ============ ORDERS ============
CREATE TABLE orders (
  org_id            uuid NOT NULL,
  order_id          uuid NOT NULL DEFAULT gen_random_uuid(),
  location_id       uuid NOT NULL,
  menu_version_id   uuid NOT NULL,           -- exact menu the guest saw
  person_id         uuid,                    -- null for anonymous walk-up
  channel           text NOT NULL CHECK (channel IN ('pos','web','marketplace','phone','kiosk','api')),
  fulfillment       text NOT NULL CHECK (fulfillment IN ('dine_in','pickup','delivery','curbside')),
  state             text NOT NULL,           -- projection; source of truth is order_events
  subtotal_cents    bigint NOT NULL,
  tax_cents         bigint NOT NULL,
  tip_cents         bigint NOT NULL DEFAULT 0,
  delivery_fee_cents bigint NOT NULL DEFAULT 0,
  service_fee_cents bigint NOT NULL DEFAULT 0,
  discount_cents    bigint NOT NULL DEFAULT 0,
  total_cents       bigint NOT NULL,
  currency          char(3) NOT NULL DEFAULT 'USD',
  idempotency_key   text NOT NULL,
  origin_device_id  uuid,
  placed_at         timestamptz NOT NULL DEFAULT now(),
  promised_at       timestamptz,
  business_date     date NOT NULL,           -- computed in location timezone
  PRIMARY KEY (org_id, order_id),
  UNIQUE (org_id, idempotency_key)
) PARTITION BY RANGE (business_date);

CREATE TABLE order_events (
  org_id       uuid   NOT NULL,
  order_id     uuid   NOT NULL,
  seq          bigint NOT NULL,              -- monotonic per order
  event_type   text   NOT NULL,
  payload      jsonb  NOT NULL,
  actor_id     uuid,
  source       text   NOT NULL,
  occurred_at  timestamptz NOT NULL,         -- device clock (may be skewed)
  recorded_at  timestamptz NOT NULL DEFAULT now(),  -- server clock (authoritative)
  PRIMARY KEY (org_id, order_id, seq)
);

-- ============ ROW LEVEL SECURITY ============
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON orders
  USING (org_id = current_setting('app.org_id', true)::uuid);
-- PgBouncer/pgcat sets app.org_id from the verified JWT claim on every checkout.
-- Application code CANNOT widen this; a missing claim yields zero rows, not all rows.

Identity, loyalty, and ledger

Fig. 01.4 — Cross-brand identity, loyalty wallet, double-entry ledgerMD-DDL-002
-- One person, many restaurants. This table is platform-scoped, NOT tenant-scoped.
CREATE TABLE persons (
  person_id     uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email         citext UNIQUE,
  phone_e164    text UNIQUE,
  display_name  text,
  marketing_consent jsonb NOT NULL DEFAULT '{}',  -- per-channel, per-org, timestamped
  created_at    timestamptz NOT NULL DEFAULT now()
);

-- Tenant-scoped view of a person. A restaurant sees only its own relationship.
CREATE TABLE customer_profiles (
  org_id        uuid NOT NULL,
  person_id     uuid NOT NULL REFERENCES persons,
  first_order_at timestamptz,
  last_order_at  timestamptz,
  order_count    int    NOT NULL DEFAULT 0,
  lifetime_cents bigint NOT NULL DEFAULT 0,
  aov_cents      bigint GENERATED ALWAYS AS
                 (CASE WHEN order_count=0 THEN 0 ELSE lifetime_cents/order_count END) STORED,
  rfm_segment    text,                        -- champion|loyal|at_risk|lapsed|new
  churn_p        real,                        -- model output, 0..1
  predicted_ltv_cents bigint,
  PRIMARY KEY (org_id, person_id)
);

-- Identity resolution: deterministic first, probabilistic second, always reversible.
CREATE TABLE identity_links (
  person_id   uuid NOT NULL,
  identifier  text NOT NULL,          -- hashed email | phone | device_id | card_fingerprint
  id_type     text NOT NULL,
  confidence  real NOT NULL,          -- 1.0 deterministic; <1.0 probabilistic
  method      text NOT NULL,          -- 'login'|'otp'|'card_fp'|'device_graph'
  linked_at   timestamptz NOT NULL DEFAULT now(),
  unlinked_at timestamptz,            -- soft-unlink preserves audit trail
  PRIMARY KEY (identifier, id_type, person_id)
);

-- Cross-brand points. Balance is a projection; ledger below is the truth.
CREATE TABLE loyalty_accounts (
  person_id      uuid PRIMARY KEY REFERENCES persons,
  points_balance bigint NOT NULL DEFAULT 0 CHECK (points_balance >= 0),
  tier           text NOT NULL DEFAULT 'bronze',
  tier_progress_cents bigint NOT NULL DEFAULT 0,
  tier_expires_at timestamptz
);

CREATE TABLE loyalty_entries (
  entry_id    bigserial PRIMARY KEY,
  person_id   uuid NOT NULL,
  org_id      uuid,                   -- earning org; NULL for platform grants
  order_id    uuid,
  delta       bigint NOT NULL,        -- +earn / −redeem / −expire
  reason      text NOT NULL,
  liability_cents bigint NOT NULL,    -- cash value moved onto/off the balance sheet
  expires_at  timestamptz,
  created_at  timestamptz NOT NULL DEFAULT now()
);

-- Double-entry. Every cent that moves creates two rows summing to zero.
CREATE TABLE journal_entries (
  journal_id  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id      uuid NOT NULL,
  order_id    uuid,
  entry_type  text NOT NULL,          -- sale|tax|tip|fee|payout|refund|chargeback|points
  occurred_at timestamptz NOT NULL DEFAULT now()
);
CREATE TABLE journal_lines (
  journal_id  uuid NOT NULL REFERENCES journal_entries,
  line_no     int  NOT NULL,
  account     text NOT NULL,          -- 'cash','ar_processor','sales','sales_tax_payable',
                                          'tips_payable','platform_fee_revenue',
                                          'loyalty_liability','driver_payable'
  debit_cents  bigint NOT NULL DEFAULT 0,
  credit_cents bigint NOT NULL DEFAULT 0,
  PRIMARY KEY (journal_id, line_no),
  CHECK (debit_cents = 0 OR credit_cents = 0)
);
-- Enforced by trigger: SUM(debit) = SUM(credit) per journal_id. A journal that does
-- not balance cannot commit. This is the difference between an accounting system and
-- a pile of numbers.
Schema decision — why loyalty is platform-scoped but profiles are tenant-scoped

A guest has one points wallet across every Mobile Dinners restaurant — that is the consumer hook, and it is what an aggregator cannot copy without cannibalizing its own commission. But a restaurant must never be able to query another restaurant's customer relationship. So persons and loyalty_accounts live outside tenant RLS, while customer_profiles is a tenant-scoped projection that exposes only the slice belonging to that org. Cross-brand aggregates reach operators only as anonymized, k-anonymized cohort statistics (minimum cohort size 25).
